DSH Backup 1.3.1 - 便携版

DSH Backup 只备份 DSH 的核心数据：登录态、API Key、会话、工作区登记、附件、用量，以及可选的桌面端登录态。
不备份项目代码、日志和缓存。备份数据只保存在本机，不上传；可选在启动时只读检查 GitHub 发行版，可在设置中关闭。

使用方法
--------
1. 将整个 DSHBackup 文件夹解压到可写目录，不要放到 C:\Program Files 等只读目录。
2. 双击 DSHBackup.exe。首次启动选择本地备份目录和是否包含桌面登录态即可。
3. “立即备份”完成后，归档位于 DSHBackup\backups，另有同名 .manifest.json 记录 SHA-256 和加密信息。

本地加密与密钥
--------------
- 默认关闭；在“设置 → 本地加密”开启后会在 data\keys 生成一对本地公钥/私钥。
- 每个归档使用独立随机密码，密码由公钥封装后写入 manifest；恢复时自动用私钥解开。
- 公私钥不配对或公钥缺失时，新的加密备份会被阻止；已有归档仍可用有效私钥尝试恢复。
- 私钥丢失或应用目录被删除后，已有加密备份无法恢复，应用不提供恢复密钥。
- 换机恢复必须同时带上 data\keys 目录。
- 如果要把备份放到共享目录、U 盘或网盘，建议开启本地加密。

恢复
----
- 请先关闭 DSH。
- “覆盖当前数据”：会先把即将被覆盖的 .dsh（以及勾选时的桌面登录态）另存为一份“恢复前快照”，完整核对后才写入。
- “恢复到其他目录”：只把 DSH 核心数据写入你选择的目录，不会触碰系统里的桌面登录态。
- 恢复不会跟随目标目录内的目录联接/符号链接；写入时先在目标文件旁生成短命候选，校验成功后替换，复制失败不会截断旧文件。
- 恢复是逐文件提交，不是整棵树的事务；中途失败不会自动回滚已写入的文件。异常退出可能留下 .dshbak-*.tmp 候选。
- 同机同 Windows 用户恢复桌面 Cookie 成功率最高；换机可能需要重新登录。
- 恢复完成后重新启动 DSH。

目录说明
--------
DSHBackup.exe            主程序
dsh-backup-core.exe      Rust sidecar（底层文件/7z 编排）
tools\7za.exe            随包分发的官方 7-Zip CLI
tools\License.txt        7-Zip 许可证
backups\                 默认本地备份目录（首次备份时创建）
data\config\             配置
data\keys\               本地公钥/私钥
data\logs\               运行日志（已脱敏）
data\temp\               任务临时文件（启动时只清理本程序标记的目录）
data\webview2\           WebView2 用户数据

注意：删除整个应用目录会连同默认本地备份和本地私钥一起删除。重要备份请另存到其他磁盘。
更新时请替换程序与 tools，不要删除 data 和 backups。

从 1.3.0 升级
-------------
- 恢复解压前增加体积预检：解压后超过归档 200 倍且大于 256 MB 时，需要确认后才会继续。
- 恢复准备会扫描目标目录，报告上次异常退出留下的 .dshbak-*.tmp 候选文件；只报告，不删除。
- 诊断包新增 restore-candidates.txt（仅在发现候选时生成）。
- 备份格式、配置文件、密钥与已有归档全部兼容，可以直接替换运行文件。

从 1.2.3 升级
-------------
- 删除归档改为瞬时移入回收站：备份目录内的 .dshbackup-trash，同盘移动，不复制归档，也不再等待 6 秒撤销窗口。
- 回收站默认保留 7 天，可在「设置 → 回收站」改为 1 / 7 / 30 / 90 天，或选择「永不」关闭自动清理；到期自动彻底删除，也可手动清空。
- 保留策略淘汰的旧备份也会进入回收站，不再直接删除。磁盘空间要等回收站清空或到期才释放。
- 找回会把归档放回当前备份目录，不覆盖同名文件；回收站与当前备份目录不在同一分区时不允许找回。
- 本应用只管理当前备份目录的回收站。切换备份目录后，旧目录里的回收站不会被自动删除，也不会显示。
- 关闭按钮可选「每次询问 / 直接退出 / 最小化到托盘」；首次会询问并可记住。留在托盘时计划备份照常触发。
- 字典大小、星期和恢复来源改用应用内选择器，不再是系统原生下拉框。
- 帮助改为带目录的长文档。备份格式、配置文件、密钥和已有归档全部兼容，可以直接替换程序与 tools。

从 1.2.2 升级
-------------
- 1.2.3 新增六档压缩：仅存储、极速、快速、均衡、高压缩、极限；新建配置默认“仅存储”。
- “仅存储”不压缩，速度最快但归档最大；均衡仍是体积与耗时的日常折中。
- 高级参数不再接受 -mx；旧配置里已有的 -mx 会自动折算到最接近的新档位，旧归档不受影响。
- 备份格式、配置文件、密钥和已有归档全部兼容，可以直接替换程序与 tools。

从 1.2.1 升级
-------------
- 1.2.2 是可靠性修复版，备份格式、配置文件、密钥和已有归档全部兼容，可以直接替换程序与 tools。
- 恢复会拒绝目标目录中的链接/重解析点；文件先写成目标旁候选，校验后再替换，复制失败不会截断旧文件。
- 恢复前快照会严格核对实际归档内容；任何缺文件或警告都会中止恢复，不覆盖当前数据。

- 取消任务会等待底层工作结束；计划任务不再每次把执行时刻推到未来，也不会追补应用关闭期间错过的时刻。
- 删除归档的撤销窗口、目录切换和重复清单处理已修正；发布包改为从干净暂存目录生成，不删除已有 data 和 backups。

从 1.0.x 升级
-------------
- 1.1.0 移除了 GitHub 云端上传和网络/代理设置。

- 如果以前把 GitHub 令牌存进了 Windows 凭据管理器，本程序不会再读取它；可在“控制面板 → 凭据管理器 → Windows 凭据”里手动删除 DSHBackup/ 开头的条目。

系统要求
--------
- Windows 10/11 x64
- Microsoft Edge WebView2 Runtime（Windows 11 通常已内置）

隐私与边界
----------
- 备份与恢复不联网；唯一可选的网络功能是启动时检查 GitHub 发行版（只读、可关闭）。日志不记录归档密码、私钥、Cookie 或 API Key。
- 只解压本应用生成的归档，并校验路径穿越和重解析点。
- 不支持项目代码备份、多账号、团队共享。
- 本工具不自动下载或安装更新；启用检查时，发现新版本会提示并可在浏览器打开发行版页面。
